
--------

The chosen project is a password manager. The password manager will contain a password vault, which contains the passwords stored. Stored passwords will be encrypted using the openssl module.
Upon first time usage, the password will have to be generated by the user, while adhering to common password safety requirements.

Password is then stretched using HKDF and vault will be created with the AES-256 CBC mode encryption.
The vault, once decrypted will be a loosely-typed JSON file that contains the following optional parameters: "identifier", "password", "notes"

For safety, the fields are limited to 255 characters. The object itself must not contain more than 1000 records.

### Threat model
#### Master password
Threat 1: The master password can be weak, leading to a compromise of passwords. 
Mitigation: Require user to use a strong password

Threat 2: The user can be extorted for their master password
Mitigation: None planned

#### The vault at rest
Threat 1: The vault file can be stolen
Mitigation: The vault file is encrypted using a strong password using AES-256 encryption.

Threat 2: The vault file can be tampered with
Mitigation: The vault file will have appropriate file permissions, so normal users can not damage its integrity

#### The vault in memory

Threat 1: The reading operations are not guarded properly (use after free, buffer overflow)
Mitigation: Code audits and secure reading functions are used

Threat 2: The write operations are implemented incorrectly and cause data loss
Mitigation: Code audits and secure reading functions are used

#### Interface

Threat 1: The interface corrupts passwords accidentally
Mitigation: Input validation, safe coding practices

Threat 2: Other applications are able to read the interface contents
Mitigation: Passwords and entries are shown only after user input
